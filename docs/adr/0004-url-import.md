# ADR-0004: Импорт статей по URL

Статус: принято.

## Решение

Fetch — отдельная операция в рамках HTTP-запроса. Бэкенд скачивает страницу, Mozilla Readability на DOM из linkedom выделяет основной материал, текст превращается в sections и сохраняется как Article в Postgres. Чтение статьи не ходит в сеть и не разбирает HTML повторно.

Скачивание — сервисный модуль WebPageModule на нативном fetch: страница принимается только с HTTP 200, тип text/html или application/xhtml+xml, лимит 10 секунд и 5 МБ. Правила импорта остаются в ArticlesModule: Readability нашёл материал, в нём не меньше 500 символов текста и есть заголовок.

## Компромиссы

- Страница читается как статический HTML, скрипты не выполняются. Сайты, которые рендерят текст JavaScript или закрывают доступ ботам, не импортируются. Первые отсекаются порогом длины текста.
- Каждый Fetch создаёт новую неизменяемую Article, даже для той же ссылки. Одинаковые тексты хранятся повторно, зато запуск всегда ссылается на тот текст, который анализировался, без версий и дедупликации.
- Своя статья и конкуренты — одна модель Article; роль задаётся связью с AnalysisRun, конкуренты связаны с запуском таблицей связей Prisma.
- Импорт ходит по любому указанному публичному адресу. Ограничение исходящих запросов сервера — ответственность его сети.

## Проверка

Смоук apps/api/src/import.smoke.ts прогоняет реальные URL через запущенный API: все ссылки тем-примеров из packages/examples/topics.json должны импортироваться, а собственный список отказов — отклоняться. Он зависит от доступности сайтов и запускается вручную, вне npm test.
