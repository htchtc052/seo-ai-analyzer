# ADR-0009: Образы в GHCR и ручной деплой

Статус: принято.

## Решение

- Один репозиторий и один набор GitHub Actions. Publish images на push в main гоняет typecheck, миграции и тесты на Postgres и Redis, затем матрицей собирает три образа в GHCR: api (NestJS и сгенерированный Prisma Client), migrate (Prisma CLI и миграции, стадия того же Dockerfile) и web (статика Vite в nginx). Deploy запускается вручную и по SSH выкатывает их вместе.
- VPS ничего не собирает и не хранит исходники: в нём sparse checkout папки infra, .env и Docker volumes. Traefik выпускает сертификат Let's Encrypt и маршрутизирует /api в API, остальное — в web, поэтому фронтенд и API на одном домене.
- Миграции применяет `prisma migrate deploy` во временном контейнере migrate до пересоздания сервисов; если миграция падает, работающие контейнеры остаются.
- Ollama установлена на хосте VPS, API обращается к ней через host.docker.internal. Compose описывает только то, что относится к приложению, и не меняется при переходе на LLM провайдера.

## Компромиссы

- Образы публикуются только с тегом latest: откат — повторная публикация нужного коммита.
- api и web выкатываются вместе, даже если изменился только один из них.
- Ollama на хосте слушает 0.0.0.0, чтобы до неё доходили контейнеры; внешний доступ закрывает файрвол.
- Runtime-зависимости api ставятся с `--omit=dev --omit=optional`: иначе npm тянет Prisma CLI и TypeScript как необязательные peer-зависимости @prisma/client. Вместе с ними не ставятся и необязательные нативные ускорители (msgpackr-extract), BullMQ работает на JS-реализации.
- Образ migrate отдельный и тяжелее api, но скачивается и запускается только при деплое.
