# ADR-0003: Раздельные контракты фронтенда и бэкенда

Общего пакета схем нет. Фронтенд и бэкенд связаны только REST API.

- Бэкенд описывает вход и выход каждого модуля Zod-схемами в `dto/`: запрос проверяет ZodValidationPipe, ответ очищает глобальный ZodSerializerInterceptor по @ResponseSchema. Сообщения ошибок нейтральны и адресованы клиенту API.
- Фронтенд держит TypeScript-типы ответов в `entities/*/model`, а форму анализа валидирует своей Zod-схемой в `features/start-analysis/contract` с текстами для пользователя.

Цели валидации разные: у бэкенда — целостность данных при любом клиенте, у формы — понятный UX. Компромисс: при изменении ответа тип правится в двух местах, и расхождение не ловится typecheck; форму ответа списка проверяет тест API.
