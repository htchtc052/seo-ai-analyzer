# ADR-0008: Фронтенд: shadcn/ui, форма на общей схеме, темы-примеры

Статус: принято.

## Решение

- Интерфейс собран из компонентов shadcn/ui (Radix + Tailwind CSS v4). Компоненты скопированы в apps/web/src/components/ui и не правятся вручную. Там же лежат собственные UI-примитивы без доменной логики, собранные из shadcn (external-link); тема — CSS-переменные в app/styles.css, только светлая.
- Структура — дефолтная раскладка shadcn, без FSD-слоёв: app (точка входа, роутер, стили), pages, components/ui (shadcn и свои UI-примитивы), components/articles и components/analysis (доменные компоненты), hooks, lib/api.ts. Features/entities/widgets и публичные index.ts для трёх страниц — лишняя обвязка.
- Логика отделена от вёрстки: загрузка, поллинг, форма и вычисление статусов живут в хуках (useNewAnalysis, useArticleImport, useAnalysisRun, useAnalysisRuns). Компоненты и страницы получают готовые значения и статусы и только отображают их; подписи и варианты Badge выбираются по статусу из таблицы.
- Форма анализа — react-hook-form с zodResolver на analysisRequestSchema из packages/contracts. Правила полей и тексты ошибок совпадают с бэкендом; отображение — Field и FieldError из shadcn.
- Темы-примеры лежат в packages/examples/topics.json: статья, два конкурента и пример запроса на тему. Файл читают форма (ссылки-примеры и выбор темы в Dialog) и смоук импорта, поэтому ссылки в интерфейсе и проверяемые ссылки не расходятся.

## Компромиссы

- Код shadcn живёт в репозитории и обновляется CLI, а не версией пакета.
- Пакет примеров — JSON без сборки и схемы: его содержимое проверяет смоук, а не типы.
- Ссылки-примеры указывают на сторонние сайты и со временем могут перестать импортироваться; это видно по смоуку.
