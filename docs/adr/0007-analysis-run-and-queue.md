# ADR-0007: Запуск анализа и очередь рекомендаций

POST /api/analyses в рамках запроса считает оценки и сохраняет AnalysisRun со всеми входными данными; если embeddings не получены, запуск не создаётся. При наличии конкурентов ставится BullMQ-джоб с jobId, равным id запуска, и attempts: 1, а воркер дописывает рекомендации в тот же запуск.

## Компромиссы

- Оценки синхронные, рекомендации в фоне: форма не держит соединение на время генерации.
- Добавить конкурентов к посчитанным оценкам нельзя — это новый запуск с повторным расчётом embeddings.
- Одна попытка: повтор генерации стоит денег и времени, а ошибка сразу видна как failed. Повторы HTTP-клиента openai — отдельный механизм, очередь их не учитывает.
- Состояние и причина ошибки джоба читаются из BullMQ и отдаются и в запуске, и в сводке истории; поля статуса в базе нет. Фронт сводит состояние к четырём исходам одной функцией: только оценки, готовятся, готовы, не получены. Запуск с конкурентами без рекомендаций и без живого джоба считается неудачным, а не вечным ожиданием.
- Удаление запуска на бэкенде не проверяет состояние джоба. Интерфейс не даёт удалить запуск, пока рекомендации готовятся; при прямом вызове API джоб может завершиться ошибкой при сохранении.
