# ADR-0007: Запуск анализа и очередь рекомендаций

Статус: принято.

## Решение

POST /api/analyses принимает статью, запрос, до двух конкурентов и контекст. В рамках запроса считает embeddings и оценки и сохраняет AnalysisRun со всеми входными данными. Если embeddings получить не удалось, запуск не создаётся.

Если конкуренты переданы, та же операция ставит в BullMQ джоб recommend с jobId, равным id запуска. Воркер дописывает недостающие темы и рекомендации в тот же запуск. Без конкурентов джоб не ставится.

## Компромиссы

- Оценки синхронные (около секунды), рекомендации — в фоне (около минуты). Пользователь видит оценки сразу, а форма не держит соединение на время генерации.
- Запуск создаётся целиком одной операцией и больше не меняется. Каждое нажатие — новый запуск со своим джобом. Добавить конкурентов к уже посчитанным оценкам нельзя: это новый анализ с повторным расчётом embeddings.
- Состояние джоба и причина ошибки берутся у BullMQ, входные данные и результаты — из Postgres. Своего поля статуса в БД нет, чтобы не держать два источника правды о выполнении. Запуск без конкурентов — результат только с оценками. Запуск с конкурентами без рекомендаций и без джоба в Redis означает, что состояние задачи потеряно.
- Ошибка генерации не удаляет оценки и не скрывает запуск из истории.
- Redis в dev-окружении работает без тома: при пересоздании контейнера состояние джобов теряется.
