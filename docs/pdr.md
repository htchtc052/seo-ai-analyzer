# SEO AI Analyzer — PDR

## Зачем

Автор хочет понять, насколько статья отвечает поисковому запросу и чего в ней не хватает по сравнению с конкурентами. Приложение показывает смысловую близость каждого абзаца к запросу и, если добавлены конкуренты, предлагает недостающие темы и конкретные правки.

Референсы: [Dan Hinckley — semantic map](https://www.linkedin.com/posts/danielhinckley_seo-ai-tip-a-semantic-map-shows-exactly-share-7474823608419291136-4lFf/), [Ammad Ur Rehman — Semantic Relevance Analyzer](https://www.linkedin.com/posts/ammad-rehman_semanticseo-generativeengineoptimization-ugcPost-7475527860489932800--qD_/).

## Сценарий

1. Пользователь вставляет ссылку на свою статью и нажимает Fetch. Приложение скачивает страницу, выделяет основной текст и показывает, сколько текста извлечено. Страница без пригодного текста даёт понятную ошибку. Так же загружаются до двух статей конкурентов.
2. Текст не редактируется. Изменение ссылки сбрасывает загруженную статью, чтобы старый текст не ушёл в анализ под новой ссылкой.
3. Анализу нужны статья и target query. Необязательный контекст — аудитория, цель материала, ниша сайта — используется только в рекомендациях.
4. Run analysis сразу считает оценки и открывает страницу результата. Если есть конкуренты, рекомендации пишутся в фоне и появляются на той же странице примерно через минуту. Ошибка генерации показывается там же и не отменяет оценки.
5. Каждый запуск сохраняется в истории и не меняется: другой набор входных данных — новый анализ.

Если на сервере не настроена модель для рекомендаций, поля конкурентов не показываются и анализ считает только оценки.

## Как считается результат

- Статья делится на фрагменты: абзац вместе с заголовком своей секции.
- Оценка фрагмента — cosine similarity embeddings фрагмента и запроса, общая оценка — среднее по фрагментам.
- Модель получает фрагменты с оценками, тексты конкурентов, запрос и контекст и возвращает недостающие темы и рекомендации.
- Cosine similarity показывает смысловую близость к запросу, а не прогноз позиции в поиске и не качество текста.
- Каждый Fetch сохраняет новую копию статьи, поэтому запуск всегда ссылается ровно на тот текст, который анализировался.
